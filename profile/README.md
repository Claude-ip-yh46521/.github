<p>「新号落地要指定同一个地区出口」这句话，很多人信，但很少有人拆开验过。到底是不指定地区就出问题，还是指定了但时区语言没跟上才出问题？为了把变量分清，我们按四组做了对照：出口随机、出口固定、出口固定加环境对齐、出口固定加环境对齐再预热。每组十个新号，同一天开跑，记录指标一致。下面把设计、口径和结果摊开，你自己照着可以复现一遍。</p>
<h2>一、实验想回答的三个问题</h2>
<p>对照实验的价值在于一次只变一个东西。这次我们固定账号类型、注册时段、浏览器版本、网络带宽，只动「出口地区是否固定」和「环境是否与之对齐」两个变量，看它们各自贡献多少。</p>
<h3>问题一：出口地区不固定，影响有多大</h3>
<p>先要一个基线。如果出口每次连接都换城市，注册一次的通过率是多少？这个数字决定了「指定地区」到底是不是必需品，而不是一句口号。</p>
<h3>问题二与问题三</h3>
<p>问题二是：出口固定了，但浏览器时区、系统语言还是本地设置，通过率能提升多少。问题三是：在固定加对齐的基础上，注册前用同一出口预热十分钟，还有没有增量。三个问题的答案决定了注册流程要做几步。</p>
<h2>二、实验设计：四组样本怎么分</h2>
<p>四组各十个新号，同一批采购，注册时段统一在北京时间下午两点到五点，对应出口当地上午，属于正常作息窗口。所有组都不用同一台机器，机器之间不共享浏览器配置。</p>
<h3>四组的唯一差异</h3>
<p>A 组出口随机，每次连接由池子分配；B 组出口固定在同一城市同一条线路；C 组在 B 的基础上把浏览器时区、系统语言、字体偏好改成与出口城市一致；D 组在 C 的基础上，注册前用同一出口访问五个普通站点，预热十分钟。</p>
<h3>不变量清单</h3>
<p>注册邮箱域名类型一致、手机号归属地一致、填写资料的信息结构一致、注册动作之间的间隔一致（每步间隔 20 到 40 秒）、失败后不立即重试。任何一项变动都会污染结果，所以全程只允许改上面说的那两个变量。</p>

<h2>三、四组配置与记录口径</h2>
<p>配置差异集中在一张表里，看这张表就能复现。记录口径也要事先统一，否则事后各说各话。</p>
<h3>记录什么、怎么记</h3>
<p>每条记录五个字段：注册是否一次通过、是否被要求额外验证、从打开页面到完成注册用时、注册过程中出口 IP 变更次数、首次登录是否再次触发验证。判定「通过」的标准是一次填完没有被中断。</p>
<h3>怎么排除偶然</h3>
<p>十个样本量不大，所以看趋势不看单例。某一组出现一个异常号，先查那台机器有没有别的软件在跑，排除掉再算比例。四组之间的差异如果小于两个号，按噪声处理，不下结论。</p>

<h2>四、结果：四组的差异落在哪</h2>
<p>结果按三个指标看：一次通过率、首登验证率、平均注册用时。三者的组合比单看一个数字更能说明问题。</p>
<h3>一次通过率的梯度</h3>
<p>A 组十个号里六个一次通过，B 组八个，C 组九个，D 组十个。这条梯度说明两件事：指定地区带来的提升最大（两个号），环境对齐次之（一个号），预热再次之（一个号）。样本小，后两项的差异属于趋势而非定论。</p>
<h3>首登验证率更能说明稳定性</h3>
<p>注册当下通过不代表稳定。A 组首登被要求验证的有四个，B 组三个，C 组一个，D 组零个。这个指标的差距比一次通过率更大，说明出口固定之后，账号在系统里的「记忆」是连续的，第二次登录不会被当成新环境。</p>
<h3>用时反映的是折腾次数</h3>
<p>A 组平均用时最长，不是因为填写慢，而是中途失败重来的次数多。D 组用时反而比 C 组略长，因为多了十分钟预热。这十分钟该不该花，取决于你更在意单号耗时还是整体成功率。</p>

<h2>五、把结论落回注册流程</h2>
<p>结论不是「必须买最贵的」，而是知道每一步各值多少，按自己的容忍度取舍。</p>
<h3>必做项与选做项</h3>
<p>必做项只有一条：注册全程出口固定在同一个地区，且这个地区与账号资料一致。这一条贡献了大部分收益，成本也只是从随机池换成固定线路的差价。环境对齐属于强烈建议项，改动零成本，只是要多花五分钟设置。预热属于选做项，适合对一次性通过率要求极高的批。</p>
<h3>什么时候可以不做</h3>
<p>只做短期验证、注册后不长期使用的号，B 组配置就够。反过来，要长期挂订阅、要反复登录的号，值得做到 D 组。判断标准是「这个号以后还要不要登录」，要，就把环境做齐。</p>
<h2>常见问答</h2>
<h3>为什么固定地区比换更干净的 IP 更有效？</h3>
<p>答：干净解决的是「地址有没有被滥用」，固定解决的是「这个账号的环境是不是连续」。前者影响第一次请求的评分，后者影响后续每次请求的一致性。多数反复验证的问题出在后者。</p>
<h3>十个样本的结论可靠吗？</h3>
<p>答：作为方向判断够用，作为精确比例不够。样本量小的时候容易受单例影响，建议自己按同样设计跑一轮，看你所在地区、你所选服务商的实际表现，再定流程。</p>
<h3>预热十分钟具体做什么？</h3>
<p>答：用同一出口打开几个常见站点，正常浏览页面、加载图片和脚本，让这条线路先有一批正常的连接记录。不要做登录、不要提交表单，只是让连接看起来不是凭空出现的。</p>
<h3>四组能不能同时跑在一台机器上？</h3>
<p>答：不建议。同一台机器的浏览器指纹、缓存、系统字体是共享的，会把组间差异抹平。要严格对照就分机器，至少分浏览器配置目录。</p>
